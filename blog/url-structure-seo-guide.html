URL 구조 · SEO

홈페이지 SEO, URL 구조는
왜 처음부터 잘 잡아야 할까

2026. 09. 23 · 이수연

검색 결과에서 제목 아래 회색으로 표시되는 그 한 줄, URL. 방문자는 거의 클릭하지 않는 부분이지만 검색엔진에게는 페이지의 위치와 성격을 알려주는 가장 압축된 정보입니다. 잘 설계된 URL 구조는 크롤링 효율, 클릭률, 그리고 사이트 전체의 정보 위계까지 함께 정리해줍니다.

좋은 URL 구조의 3가지 원칙

1. 짧고 예측 가능해야 한다

URL만 보고도 방문자가 어떤 페이지인지 짐작할 수 있어야 합니다. /blog/homepage-seo는 예측 가능하지만, /view.php?id=8231&cate=12는 어떤 정보도 전달하지 못합니다.

2. 키워드는 넣되 욱여넣지 않는다

핵심 키워드 한두 개를 슬러그에 포함시키는 것은 도움이 되지만, /best-cheap-homepage-design-agency-seoul-2026처럼 키워드를 나열하는 방식은 오히려 스팸으로 보일 수 있습니다.

3. 구조가 사이트의 위계를 반영해야 한다

카테고리, 하위 카테고리, 개별 페이지의 관계가 URL 경로에 자연스럽게 드러나면 검색엔진이 사이트 구조를 훨씬 빠르게 파악합니다.

피해야 할 URL 패턴

패턴문제점대안
동적 파라미터 남용?id=123&sort=asc&page=2 — 중복 콘텐츠로 인식될 위험정적 슬러그 사용, 불가피할 경우 canonical 태그 병행
대문자·특수문자 혼용대소문자를 다르게 인식하는 서버에서 중복 URL 발생소문자와 하이픈(-)만 사용
세션 ID 노출;jsessionid=... — 방문할 때마다 다른 URL 생성쿠키 기반으로 세션 관리
과도한 뎁스/shop/category/sub/sub2/product — 크롤링 우선순위 하락2~3단계 이내로 단순화

실전 예시

❌ https://example.com/index.php?page_id=48&cat=3
✅ https://example.com/service/branding

❌ https://example.com/2026/09/23/이것이-홈페이지-제작-비용-정말-모든-것을-담은-글입니다
✅ https://example.com/blog/homepage-making-cost

❌ https://example.com/product?id=8821
✅ https://example.com/product/organic-hand-cream

하이픈(-) vs 언더스코어(_)

구글은 하이픈을 단어 구분자로 인식하지만 언더스코어는 단어를 이어 붙인 것으로 해석하는 경향이 있습니다. homepage_seo보다 homepage-seo가 검색엔진이 각 단어를 개별 키워드로 인식하기에 유리합니다.

URL 구조와 canonical, 사이트맵의 관계

URL을 정리했다면 그 URL이 canonical 태그와 사이트맵에 등록된 주소와 정확히 일치하는지도 함께 확인해야 합니다. 구조화 데이터 안의 url 값 역시 마찬가지입니다.

→ 구조화 데이터(Schema Markup) 완벽 가이드

→ XML Sitemap과 robots.txt 완벽 가이드

리뉴얼 시 URL을 바꿔야 한다면

기존 URL을 바꾸는 것은 SEO 관점에서 가장 위험한 작업 중 하나입니다. 반드시 301 리다이렉트 맵을 미리 만들어두고 하나씩 확인해야 합니다.

→ 홈페이지 리뉴얼할 때 SEO 순위 떨어뜨리지 않는 법

정리하며

URL은 한번 정하면 쉽게 바꾸기 어려운 요소입니다. 페이지를 처음 만들 때부터 짧고 예측 가능한 구조로 설계해두면, 이후 콘텐츠가 아무리 늘어나도 사이트 전체가 정돈된 상태를 유지할 수 있습니다.

자주 묻는 질문

URL에 한글을 써도 되나요, 영문 슬러그가 나은가요?

구글은 한글 URL도 인코딩해서 정상적으로 인식하지만, 실제로 공유되거나 브라우저 주소창에 표시될 때 깨져 보이는 경우가 많아 가독성이 떨어집니다. 가능하면 짧은 영문 슬러그를 쓰고, 한글 키워드는 title과 본문에 충분히 녹이는 방식을 권장합니다.

URL 뎁스(depth)는 몇 단계까지가 적당한가요?

정답은 없지만 일반적으로 도메인 이후 2~3단계 이내를 권장합니다. /blog/글제목 처럼 얕은 구조가 크롤링과 기억, 공유 모두에 유리합니다. 카테고리가 꼭 필요하다면 /카테고리/글제목 정도로 제한하는 것이 좋습니다.

이미 만든 URL을 나중에 바꿔도 되나요?

가능하지만 반드시 301 리다이렉트를 함께 설정해야 합니다. 리다이렉트 없이 URL만 바꾸면 기존에 쌓인 검색 순위와 백링크가 모두 사라집니다. 리뉴얼 시점의 URL 변경 체크리스트는 본문의 연결 글을 참고하세요.
